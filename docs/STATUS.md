更新日期：2026-07-22。

## 本版完成范围

P0 与本项目相关的 P1 基础设施已完成：岗位画像、证据、追问、确认、版本、质量门、发布、关闭、软删除、审计、身份、企业隔离、持久会话、显式图编排、静态 Skill、PostgreSQL 后端、指标和离线评测。

明确排除：

- 推荐匹配；
- 校招地图；
- 广播文案；
- 猎头服务；
- A2A 预先沟通。

## 关键实现

| 领域 | 实现 |
|---|---|
| 编排 | `EnterpriseHrAgent` 使用命名节点、条件转移、最大步数和节点轨迹的显式状态图 |
| 岗位编辑 | 原 `JobCsvAgent` 保留为受控 Capability，不再承担跨能力编排 |
| 对话状态 | 与岗位生命周期分离，兼容保留旧 `phase` 字段 |
| Contracts | 独立 `hr_agent_contracts` 包，所有跨模块协议含 `schema_version` |
| 岗位存储 | PostgreSQL/SQLite 保存租户、版本、生命周期、Review 和审计 |
| CSV | 仅作为 Text2SQL 兼容投影；删除投影行不丢失控制面历史 |
| 追问 | 单轮一个问题，保存结构化问题/回答和跨轮问题预算 |
| Critic | 确定性质量门；可注入一个只读 Advisory Reviewer，最多执行一次 |
| Skill | 仅加载服务端 allowlist 内静态 Pack；Skill 不能授予写权限 |
| 权限 | 企业和操作者隔离；写入、发布角色分离；可强制 HMAC 签名身份 |
| 并发 | 会话版本和岗位版本分别做乐观并发控制 |
| 可观测性 | 保存工作流节点、耗时、状态、错误类型；提供企业级 `/metrics` |

## 发布门槛

岗位必须存在公司、岗位名和职责/要求，不能存在要求属性冲突，并通过质量审查。保存成功后状态为 `REVIEWED` 或 `NEEDS_CLARIFICATION`；只有 `REVIEWED` 可以显式发布。

敏感用工条件会产生合规警告，不由模型静默删除企业原文。发布权只授予 `hr_admin` 和 `company_admin`。

## 已知边界

- HMAC 身份适合自托管 P0；接入企业 SSO/OIDC 时应替换 `IdentityProvider`，业务层无需改动。
- CSV 与控制面是跨存储同步；正式环境建议将 CSV 作为异步生成投影并监控同步失败。
- Advisory LLM Critic 默认不启用，避免额外成本和不可预测循环；确定性质量门始终启用。
- 外部 DeepSeek 的稳定性仍依赖运行环境密钥和网络。
