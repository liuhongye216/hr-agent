# 项目功能状态

更新日期：2026-07-16。

## 已完成

- 将采集 JSONL 无损展开为源 CSV，并生成固定 24 列的业务 `jobs.csv`。
- 规则抽取薪资、学历、经验、招聘类型、用工类型和办公模式。
- 可选 DeepSeek 长文本抽取；外发数据前必须显式授权，抽取结果必须有原文证据。
- 将岗位文本拆成原子语义事实，区分职责、任职要求、技能、福利与待澄清项。
- 区分 `explicit / inferred / user_confirmed`；未经确认的推断不进入正式字段。
- 修复“从0开始预训练大模型”误入任职要求的问题，并支持职责-only 新建草稿。
- 自然语言新增、修改、删除、模糊查询、候选消歧、差异预览和确认写入。
- Repository 文件锁、同目录临时文件原子替换、内容哈希及语义写入闸门。
- 写入后重建 SQLite；规则优先、LLM 回退的只读 Text2SQL 查询。
- SQL 单语句、关系白名单、危险关键字、参数数量和最大返回行数检查。
- FastAPI 会话接口和 Chainlit 本地交互界面。
- 33 项自动化测试；业务 CSV 当前 100 条，JSON 数组列可解析。

## 部分完成

- 追问：预训练职责已有定向追问和 inferred 建议，但尚无独立的追问优先级、问题预算和回答协议服务。
- 共享协议：已有会话内 `SemanticFact`，尚未形成带 `schema_version` 的独立 contracts Python 包。
- 编排：`job_csv_agent` 内有 LangGraph 状态机，但尚未实现跨抽取、追问、发布、检索、匹配的统一工作流。
- 接口：FastAPI 可本地使用，但没有认证、企业租户隔离、限流和生产级错误追踪。

## 未完成

- 岗位版本、结构化 `JobPatch`、软删除、回滚和审计日志。
- Redis/数据库会话存储和多 worker 并发语义。
- 候选人授权字段管理、硬条件过滤、关键词/向量召回与去重。
- 统一匹配服务/A2A 网关、匹配评分和可解释差距输出。
- 生产数据库迁移、备份恢复、指标监控和部署流水线。
- 完整端到端浏览器测试与真实外部 LLM 的契约测试。

## 是否需要调整功能

当前 MVP 主链路无需为了发布而重构，现有 CSV 与 Text2SQL 兼容性应保持。下一阶段建议按以下顺序扩展：

1. 把 `SemanticFact`、追问答案和 `JobPatch` 提升为带版本号的共享协议。
2. 增加岗位版本、软删除和审计日志，再替换 CSV 为生产数据库。
3. 增加认证、企业隔离与持久会话后，再部署 API。
4. 在数据授权边界明确后实现候选人 retrieval，最后接 matching gateway。

不建议现在同时重写全部占位模块；先稳定协议和审计链路，可避免后续检索与匹配重复返工。
